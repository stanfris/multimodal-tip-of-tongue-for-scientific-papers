Task 1 — Original Query Annotation
The first workflow evaluates queries stored in:
queries.json
Inspect the actual structure of this file rather than assuming its schema.

the high-level domain;
the paper/document identifier.
Use those values to locate the correct PDF within the existing PDF directory hierarchy.
Do not rely on fuzzy title matching if a deterministic domain + identifier mapping is available.

Annotation page layout
The annotation interface should be optimized for reading a scientific paper and judging a query simultaneously.
Use a two-column desktop layout.
Left side — PDF
The left side should occupy approximately 60–70% of the available width.
Display the complete PDF for the associated document.
Requirements:
PDF must be readable directly in the browser;
annotator must be able to scroll through the entire document;
zooming should be available through the viewer if possible;
do not display only a screenshot or first page;

Prefer the existing PDF-viewing mechanism if one already exists.
If the project already uses PDF.js or another PDF viewer, reuse it.



Right side — Query and annotations
The right side should occupy approximately 30–40% of the screen and remain easy to read while the user examines the PDF.
At the top, prominently display:
Query
Show the complete query using large, highly readable typography.
The query must be visually separated from the annotation controls.
Do not expose information that is not intended for annotators, such as hidden ground-truth labels or unnecessary document identifiers.
Below the query, create two clearly distinct annotation sections.



Annotation 1 — Relevance
Question:
How relevant is this document to the information need expressed by the query?
Provide exactly three selectable values:
0 — Not relevant
The document does not satisfy the information need expressed by the query.
1 — Partially relevant
The document relates to the query, but only partially addresses the information need or the match is ambiguous.
2 — Highly relevant
The document clearly corresponds to and satisfies the information need expressed by the query.
Use a visually clear control such as three large radio buttons, segmented buttons, or cards.
The annotator must select exactly one value.
Store the result as an integer:
relevance: 0 | 1 | 2



Annotation 2 — Query Well-Formedness
Question:
How well-formed and understandable is the query as a paper re-finding request?
Provide exactly three values:
0 — Poor
The query is incoherent, unusable, contradictory, severely underspecified, or does not resemble a meaningful paper re-finding request.
1 — Acceptable
The query is understandable but contains noticeable ambiguity, awkward wording, missing context, or other quality issues.
2 — Good
The query is coherent, natural, sufficiently informative, and clearly expresses a plausible information need for re-finding a scientific paper.
Store this as:
well_formedness: 0 | 1 | 2
Keep this section visually distinct from the relevance annotation so annotators do not confuse the two judgments.
